# Credential Verification

`POST /api/v2/credential-verification` — look up a professional license in the provider registry.
Registry lookups can take 10–60s — use a generous timeout.

## The full flow: state → license type → verify

Don't hard-code state or license-type codes — **discover them**. Three calls, one SDK client:

```javascript
import { VerifyClient } from "@valyd/sdk";  // v1.10.3+
const verify = new VerifyClient({ apiKey: process.env.VALYD_API_KEY });

// 1) Which states are supported → pick a stateCode (e.g. "CT")
const states = await verify.credentials.states();
//   [{ stateName: "Connecticut", stateCode: "CT", providerCount, mappingCount }, …]

// 2) Which license TYPES that state supports → pick a type.code (this IS the license type)
const types = await verify.credentials.types("CT");
//   [{ code: "ct_type_120", displayName: "Acupuncturist", category: "medicine" }, …]

// (optional) which registry/provider offers them — pins a specific source
const providers = await verify.credentials.providers("CT");
//   [{ providerCode: "elicense_ct_gov", providerDisplayName: "eLicense CT",
//      requiredFields: ["license_number"], … }, …]
// …or narrow types to one provider: verify.credentials.types("CT", "elicense_ct_gov")

// 3) Verify — licenseType is the type code from step 2 (NOT the providerCode)
const result = await verify.standalone.credentialVerification({
  firstName: "Jane",
  lastName: "Doe",                 // always send a name, even if requiredFields omits it
  licenseState: "CT",              // stateCode from step 1
  licenseType: "ct_type_120",      // the type.code from step 2 — the license type
  licenseNumber: "A12345",
  // providerCode: "elicense_ct_gov",  // optional — pin a specific registry/provider
});
// result.status: "passed" | "failed" — registry match + license status in result.data
```

`licenseType` is the license type (a `type.code` from `credentials.types`); `providerCode` is the
optional registry/source (a `providerCode` from `credentials.providers`) — they are different
things. A provider's `requiredFields` tells you which inputs to collect (always add first / last
name — the registry lookup needs it). Full parameter and response detail is below.

**Method:** POST
**Full URL:** `https://idp.valyd.work/api/v2/credential-verification`
**Auth header:** `X-API-Key: <App API key>`
**Content-Type:** `application/json`

**Fields:**
- `first_name` (string) **required** — Required even when `required_fields` omits it — the registry always needs a name.
- `last_name` (string) **required** — Or supply `full_name` instead of first/last.
- `license_type` (string) **required** — The license type: a `code` from
  [`credentials.types`](#the-full-flow-state--license-type--verify) (e.g. `'ct_type_120'`), or a
  canonical type where supported.
- `provider_code` (string) — Optional registry/source to pin, a `providerCode` from
  [`credentials.providers`](#the-full-flow-state--license-type--verify) (e.g. `'elicense_ct_gov'`).
  Distinct from `license_type`.
- `license_state` (string) **required** — 2-letter state code. Alias: `state`.
- `license_number` (string) **required** — Alias: `license_no`.
- `npi` (string) — Optional NPI when applicable.

**Request:**

<Tabs.Tab>

```javascript
import { VerifyClient } from "@valyd/sdk";
const verify = new VerifyClient({ apiKey: process.env.VALYD_API_KEY });

const { check } = await verify.standalone.credentialVerification({
  firstName: "Jane",
  lastName:  "Doe",
  providerCode: "MD",
  licenseState: "CA",
  licenseNumber: "A12345",
  npi: "1234567890", // optional
});
// check.data.match, check.data.license
```

</Tabs.Tab>
<Tabs.Tab>

```bash
curl -X POST https://idp.valyd.work/api/v2/credential-verification \
  -H "X-API-Key: $VALYD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Jane",
    "last_name":  "Doe",
    "license_type":   "MD",
    "license_state":  "CA",
    "license_number": "A12345",
    "npi": "1234567890"
  }'
```

Registry lookups can take 10–60s — add `--max-time 90`.

</Tabs.Tab>

  "match": true,
  "license": {
    "license_number": "A12345",
    "status": "active",
    "issued_at": "2015-01-01",

## Credential discovery

Use these endpoints to build state and license-type pickers in your UI before calling `credential-verification` or [`kyc-credential`](/verifications/standalone/kyc-credential). A provider's `required_fields` tells you which license inputs to collect — but always collect first / last name even when it isn't listed, because the registry lookup needs it.

### GET /api/v2/credential/states — list states

**Method:** GET
**Full URL:** `https://idp.valyd.work/api/v2/credential/states`
**Auth header:** `X-API-Key: <App API key>`

**Request:**

<Tabs items={['SDK', 'cURL']} storageKey="valyd-lang">
<Tabs.Tab>

```javascript
const states = await verify.credentials.states();
// states: [{ stateName: "California", stateCode: "CA", … }]  (SDK maps to camelCase)
```

</Tabs.Tab>
<Tabs.Tab>

```bash
curl https://idp.valyd.work/api/v2/credential/states \
  -H "X-API-Key: $VALYD_API_KEY"
```

</Tabs.Tab>
</Tabs>

**Expected output:** HTTP 200 with the standard envelope (`success: true`); `data` is:

```json
{ "states": [ { "state_name": "California", "state_code": "CA" } ] }
```

### GET /api/v2/credential/states/\{state\}/providers — list providers for a state

`{state}` is a 2-letter state code (e.g. `CA`).

**Method:** GET
**Full URL:** `https://idp.valyd.work/api/v2/credential/states/{state}/providers`
**Auth header:** `X-API-Key: <App API key>`

**Request:**

<Tabs items={['SDK', 'cURL']} storageKey="valyd-lang">
<Tabs.Tab>

```javascript
const providers = await verify.credentials.providers("CA");
// providers: [{ providerCode, providerDisplayName, credentialName, requiredFields, … }]  (camelCase)
```

</Tabs.Tab>
<Tabs.Tab>

```bash
curl https://idp.valyd.work/api/v2/credential/states/CA/providers \
  -H "X-API-Key: $VALYD_API_KEY"
```

</Tabs.Tab>
</Tabs>

**Expected output:** HTTP 200 with the standard envelope (`success: true`); `data` is:

```json
{
  "providers": [
    {
      "provider_code": "MD",
      "provider_display_name": "Medical Board of California",
      "credential_name": "Physician & Surgeon",
      "required_fields": ["license_number"]
    }
  ]
}
```
